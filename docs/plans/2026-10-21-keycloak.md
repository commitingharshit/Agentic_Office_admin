## Notes
- Keycloak 26.4.0 needs `KC_HOSTNAME` to be the exact URL browsers use (it is the token issuer). It is `http://127.0.0.1:8180` while only tested through an SSH tunnel; it changes at cutover (the realm's admin-console redirect uses `AO_PUBLIC_URL`).
- macOS `tar` adds `._*` files that Keycloak tries to import as realms: ship with `COPYFILE_DISABLE=1` or delete them (done on the host).

## The cutover (DONE 2026-10-21; kept as the record and the rollback guide)
The owner published the gate (Funnel on port 10000 to the gatekeeper) and added Keycloak's Google redirect address; I then set `KC_HOSTNAME`, switched the API and the console to Keycloak (env backups: `.env.pre-keycloak.bak` in each deploy folder on the host) and verified live: `keycloak-gate-check.sh` against the public address 17/17 from the open internet; `keycloak-check.mjs` against the public Keycloak and the live API: a new Keycloak sign-in swapped for a device token at `/v1/auth/exchange`, the token worked, sign-out stopped it, the throwaway account removed (Keycloak admin interface correctly 404 on the public address); `GET /v1/auth/config` now sends the app to Keycloak; `/admin` redirects to Keycloak. Also checked: pressing Google on Keycloak's login page reaches Google's own sign-in page with the broker redirect address and no `redirect_uri_mismatch`, so the redirect registered in Google is right. **Not yet done: a real Google sign-in through Keycloak by the owner (desktop app and admin console), and retiring Better Auth.** Rollback: empty `KEYCLOAK_ISSUER` in the accounts-sync and control-plane `.env` files and recreate those services; the old sign-in resumes. The steps were:
1. **Allow Funnel** for the node in the Tailscale admin console (Access controls: the `funnel` node attribute).
2. **Publish the gate** (root, in a terminal on the host): `sudo tailscale funnel --bg --https=10000 http://127.0.0.1:8181`. Then from anywhere on the internet: `scripts/dev/keycloak-gate-check.sh https://tanmay-hp-linux-server.tail41864f.ts.net:10000` must pass (17 paths).
3. **Tell Keycloak its public address**: in `~/ao-control-plane/keycloak/deploy/.env` set `KC_HOSTNAME=https://tanmay-hp-linux-server.tail41864f.ts.net:10000`, then `docker compose up -d`.
4. **Google**: add `https://tanmay-hp-linux-server.tail41864f.ts.net:10000/realms/agentic-office/broker/google/endpoint` to the OAuth client's authorized redirect URIs.
5. **Switch the API**: in the accounts-sync `.env` set `KEYCLOAK_ISSUER=https://tanmay-hp-linux-server.tail41864f.ts.net:10000/realms/agentic-office`, `KEYCLOAK_JWKS_URL=http://keycloak:8080/realms/agentic-office/protocol/openid-connect/certs`, `KEYCLOAK_ADMIN_URL=http://keycloak:8080`, `KEYCLOAK_API_SECRET=<Keycloak's AO_API_CLIENT_SECRET>`; recreate the api. From this moment the app is sent to Keycloak to sign in.
6. **Switch the console**: in the control-plane `.env` set `KEYCLOAK_ISSUER` (same), `KEYCLOAK_INTERNAL_URL=http://keycloak:8080/realms/agentic-office`, `KEYCLOAK_CONSOLE_SECRET=<AO_ADMIN_CONSOLE_SECRET>`; recreate the web service.
7. **First sign-in**: each real admin signs in with Google through Keycloak; their account is linked by verified email and keeps its id, role and data. Then run the desktop flow for real and tick the checklist.
The old sign-in keeps working until step 5; undoing step 5 or 6 (empty the variables) returns to it.

## After the cutover: the sign-in loop, and the Keycloak look (2026-10-21)
- **The loop (fixed).** The owner's first Google sign-in on the admin console ended on the old sign-in page again and again. Keycloak itself had worked every time (its event log shows the Google login and the code exchange); our console's callback failed after that. The cause was my own wiring: compose passes every unset setting as an EMPTY string, and the console treated an empty `AO_SYNC_API_URL` as set, so it had no API address and sent every sign-in to `/?signin=failed`, whose "Sign in" link went to the old page. Fixed by reading empty settings as unset in every place (`||` not `??`), by naming the failed step in the server log (never a token, code or secret), by sending the home page's sign-in link to Keycloak in Keycloak mode and explaining failures (`?signin=expired|cancelled|unverified|failed`), and by running the console test with empty values exactly as compose passes them (mutation-checked: with `??` it fails). `desktop-signin-flow.mjs` drives the real desktop window through the public Keycloak: window starts signed out, Continue with Google asks for Google directly (`kc_idp_hint`), the browser step returns to the app, the window shows the person signed in: all pass.
- **The look.** `services/keycloak/theme/agentic-office/login`: built on Keycloak's own v2 theme so every flow keeps working, with the real logo, the app's and console's tokens, system font, dark by default and light on request, and styled sign-in, registration, reset-password, error and one-time-code pages, phone width included; messages reworded ("Sign in to Agentic Office", "New to Agentic Office?"). The realm uses it (`loginTheme`, set live and in the realm file); theme caching is on in production (`KC_THEME_CACHE=false` turns it off while working on the look).
- **Verified live:** `keycloak-check.mjs` 26/26 against the public Keycloak and the live API (admin side through a tunnel to the private port), gate check 17/17, desktop flow all pass, control-plane suite 38/38, accounts-sync 142 (141 pass, 1 skipped for MinIO), desktop account tests 56 pass.
